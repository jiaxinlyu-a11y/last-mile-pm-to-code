Short Story Expander

本地单人使用的短篇小说扩写工作台：你写剧情指令，Codex 按段落扩写正文。本页根据项目代码和文档整理，每条都标了证据文件。

1. 操作流程：跟着操作走一遍

每条流程从你在网页上的一次操作开始，一步步写到数据存进哪里。每步先写发生了什么，再写用到的技术各自干了什么，最后是对应文件：文件路径、这个文件管什么、这一步用到的函数（文件里一段有名字、专门干一件事的代码）。

这个项目的主要流程
  1. 扩写一段正文（7 步）
  2. 手动保存一段（指令和正文）（4 步）
  3. 全文压缩（从生成到替换正文）（6 步）
  4. 全文去 AI 腔（3 步）
  5. 导出正文为 txt（3 步）
  6. 新建和删除项目（2 步）

人物、Skill 的新建、修改、删除，都是“表单 → Server Action → Drizzle 写数据库 → 刷新页面”的简单流程，这里不再展开。

流程 A：扩写一段正文

场景：你写好了某一段的写作指令，点了“准备并复制 Codex 任务”。

1
你点按钮 界面层

网页上的“准备并复制 Codex 任务”按钮被点击，前端去调用后端；后端成功后，前端把一句固定指令复制到剪贴板。

用到的技术
  • React：画出按钮；点击时运行 prepareTask；等待期间按钮显示“准备中…”（useTransition）
  • Next.js Server Actions：前端像调用普通函数一样调用后端的 prepareCodexTaskAction，Next.js 在背后自动把请求发给后端
  • 浏览器剪贴板 API：navigator.clipboard 把固定指令复制到剪贴板
对应文件
  • src/app/projects/[id]/workspaces.tsx段落区域的界面，开头写着 "use client"，表示在浏览器里运行prepareTask：按钮被点击时执行
2
后端接手 应用层

后端收到请求，交给真正干活的代码；如果出错（比如没填写作指令），把原因整理成文字返回网页。

用到的技术
  • Next.js Server Actions：文件开头写着 "use server"，表示里面的函数只在后端运行，前端可以直接调用
  • try / catch：出错时接住错误，不让页面崩掉，而是返回一句错误说明
对应文件
  • src/app/actions.ts所有按钮操作的后端入口prepareCodexTaskAction：转交任务、出错时整理错误信息
3
从数据库收集材料 数据访问层

按顺序读出：项目设置、所有段落、启用的 Base Skill、本项目选的风格 Skill、全部人物；如果当前段标了高潮，再读高潮 Skill。

用到的技术
  • Drizzle ORM：用代码写查询，比如 db.select().from(skills).where(...)，代替手写 SQL
  • better-sqlite3：Drizzle 背后真正去打开 story.db 文件读数据的驱动
  • SQLite：数据存放的地方
对应文件
  • src/lib/codex-task.ts准备扩写任务的总负责人prepareCodexTask：查数据库、读正文、写任务单，第 3–5 步都由它指挥
  • src/db/index.ts建立数据库连接，提供上面用到的 db
4
从正文里找前文 数据访问层

读 content.md，严格检查段落标记的数量、ID、顺序和数据库一致，不一致就停下；再从当前段往前找，取最近一段有正文的内容作为“前文”。

用到的技术
  • Node.js 文件读写（fs）：readFileSync 读出 content.md 的全部文字
  • 正则表达式：按格式认出 <!-- STORY_BLOCK_START:段落ID --> 这样的标记
对应文件
  • src/lib/project-content.ts所有读写 content.md 的代码都在这里readProjectContent：读正文并做严格检查
  • src/lib/codex-task-format.ts负责任务单的内容和格式selectRecentStory：挑出“前文”那一段
5
拼成任务单并安全写入 数据访问层 → 存储层

把材料拼成一份任务单，写明“只改目标段落、不改其他段落和标记”；先写临时文件，再确认 content.md 这期间没被改过，最后替换成 codex-task.md。

用到的技术
  • 模板字符串：把各部分材料按固定顺序拼成一份 Markdown 文字
  • Node.js 文件读写（fs）：writeFileSync 先写临时文件，renameSync 再一次性改名替换
  • 内容比对：写之前把 content.md 重新读一遍，和开始时读到的逐字节比较
对应文件
  • src/lib/codex-task-format.ts负责任务单的内容和格式buildCodexTaskDocument：把材料排成任务单文字
  • src/lib/codex-task.ts准备扩写任务的总负责人prepareCodexTask 的最后一段：安全写入
  • data/projects/<项目ID>/codex-task.md生成的任务单，Codex 要读的就是它
6
Codex 写正文 外部 AI

你把复制的指令粘贴给 Codex，它读任务单，只覆盖 content.md 里目标段落标记之间的正文。

用到的技术
  • Codex（VS Code）：AI 写手，读任务单、改文件；这一步不经过你的应用
对应文件
  • data/projects/<项目ID>/codex-task.mdCodex 读的任务单
  • data/projects/<项目ID>/content.mdCodex 改的正文
7
回到网页时检查 界面层 → 数据访问层

页面重新打开时读 content.md：标记格式不对（重复、嵌套、没闭合），或出现数据库里没有的段落 ID，就在页面上显示错误；数据库里有、文件里缺的段落，会自动补上空的标记。

用到的技术
  • Next.js 服务器组件：page.tsx 没有 "use client"，在后端运行，打开页面时直接读数据库和文件
  • Drizzle ORM：读出这个项目的段落列表
  • Node.js 文件读写 + 正则表达式：读 content.md 并认出每个段落标记
对应文件
  • src/app/projects/[id]/page.tsx项目工作台页面，每次打开都会先读数据库和正文页面加载时调用 syncProjectContent
  • src/lib/project-content.ts所有读写 content.md 的代码都在这里syncProjectContent：对照数据库检查正文标记，缺的补上

流程 B：手动保存一段（指令和正文）

场景：你在网页上改了某段的写作指令或正文，点“保存”。

1
提交表单 界面层

保存按钮提交整张表单，包括指令、建议字数、是否高潮、正文，以及打开页面时这段正文的“指纹”。

用到的技术
  • React 表单 + useActionState：把表单交给后端函数，等待时按钮显示“保存中…”，结果回来后显示成功或错误提示
  • Next.js Server Actions：表单直接调用后端 saveBlock
对应文件
  • src/app/ui.tsx通用小组件SaveForm：所有“保存”表单共用的外壳
  • src/app/projects/[id]/workspaces.tsx段落区域的界面把 saveBlock 交给 SaveForm
2
检查正文有没有被别人改过 应用层 → 数据访问层

后端先读出当前的 content.md，算出这段正文的指纹，和打开页面时的指纹比较；不一样，说明你在 VS Code 或 Codex 里改过，就拒绝保存并提示刷新。

用到的技术
  • SHA-256 指纹：contentHash 给正文算出一串固定长度的指纹，改一个字就会变
  • Node.js 文件读写：读 content.md
对应文件
  • src/app/actions.ts所有按钮操作的后端入口saveBlock：保存段落的全部流程
  • src/lib/project-content.ts所有读写 content.md 的代码都在这里syncProjectContent、contentHash
3
数据库和正文一起写 数据访问层 → 存储层

在一个“事务”里：先更新数据库里的指令、字数、高潮标记，并确认正好改了 1 行；再把正文写进 content.md 对应段落。任何一步失败，数据库的改动会撤销。

用到的技术
  • 数据库事务（db.transaction）：把几步操作打包，要么全部成功，要么全部撤销
  • 回读检查：result.changes !== 1 就报错，确认真的改到了这一段
  • 临时文件 + 改名：正文先写临时文件再替换，写入前后都再确认文件没被别人改
对应文件
  • src/lib/project-content.ts所有读写 content.md 的代码都在这里replaceBlockContent → write：安全写入
  • data/projects/<项目ID>/content.md正文
  • data/story.db数据库
4
刷新页面数据 应用层

保存成功后，让这个项目页面重新取一次最新数据。

用到的技术
  • Next.js revalidatePath：通知 Next.js 这个页面的数据过期了，下次显示时重新读取
对应文件
  • src/app/actions.ts所有按钮操作的后端入口refresh：调用 revalidatePath

流程 C：全文压缩（从生成到替换正文）

场景：正文写完了，你在“全文压缩”标签页填了目标字数，点“生成压缩任务”。

1
检查目标字数 应用层

后端先检查你填的目标字数是否合法，不合法直接返回错误。

用到的技术
  • Next.js Server Actions：前端直接调用 prepareCompressionTaskAction
  • 输入校验：parseCompressionTargetWordCount 检查字数格式
对应文件
  • src/app/actions.ts所有按钮操作的后端入口prepareCompressionTaskAction
  • src/lib/compression-format.ts压缩相关的格式、字数统计和校验parseCompressionTargetWordCount
2
拼压缩任务并记下“原文指纹” 数据访问层 → 存储层

读出段落顺序、压缩 Skill 和全文（严格检查标记）；正文为空就停下。拼好任务单，同时另存一个小文件，记下原文的指纹和段落顺序。写完再确认原文没被改过，否则删掉刚写的两个文件并报错；最后删掉旧的候选稿。

用到的技术
  • Drizzle ORM：读段落顺序、是否高潮、压缩 Skill
  • SHA-256 指纹：记下生成任务那一刻原文的指纹，之后每一步都拿它比对
  • JSON 文件：用 .compression-preview-meta.json 保存指纹和段落顺序
  • 原子写入（atomicWrite）：先写临时文件再替换
对应文件
  • src/lib/compression-task.ts全文压缩的整个流程prepareCompressionTask
  • data/projects/<项目ID>/codex-compression-task.md压缩任务单
  • data/projects/<项目ID>/.compression-preview-meta.json原文指纹和段落顺序（隐藏文件）
3
Codex 写候选稿 外部 AI

你把指令交给 Codex，它把压缩后的全文写进候选稿文件，不碰正式正文。

用到的技术
  • Codex（VS Code）：按压缩 Skill 删减重复、合并同功能内容，保留标记
对应文件
  • data/projects/<项目ID>/compression-preview.md压缩候选稿
4
网页显示候选稿前先检查 数据访问层

页面读取候选稿前检查三件事：段落结构有没有变、原文指纹有没有变、候选稿的标记是否和段落一一对应。任何一项不对，就提示你重新准备。

用到的技术
  • SHA-256 指纹比对：原文自生成任务后被改过就拒绝
  • 正则表达式：解析候选稿里的段落标记
对应文件
  • src/lib/compression-task.ts全文压缩的整个流程readCompressionPreview
5
你修改并保存候选稿（可选） 界面层 → 数据访问层

你可以在右侧手动改候选稿，点“保存压缩稿”。只写候选稿，不写正式正文；保存前同样检查原文指纹、段落标记，以及候选稿在你打开后有没有被别人改。

用到的技术
  • Next.js Server Actions：调用 saveCompressionPreviewAction
  • 原子写入 + 指纹：atomicWrite 带着候选稿的指纹写入，指纹对不上就拒绝
对应文件
  • src/lib/compression-task.ts全文压缩的整个流程saveCompressionPreview
6
确认替换正文 界面层 → 数据访问层 → 存储层

点“确认替换正文”，浏览器先弹出二次确认；确认后，后端再检查原文指纹和标记顺序，都对才用候选稿替换 content.md，然后删掉候选稿和指纹文件。

用到的技术
  • 浏览器确认框（window.confirm）：防止误点
  • SHA-256 指纹比对：原文在候选稿生成后被改过，就拒绝替换
  • 临时文件 + 改名：安全写入新正文
对应文件
  • src/app/projects/[id]/workspaces.tsx全文压缩区域的界面确认框
  • src/lib/compression-task.ts全文压缩的整个流程applyCompressionPreview → discardCompressionPreview
  • src/lib/project-content.ts所有读写 content.md 的代码都在这里replaceProjectContent：带指纹检查的整篇替换

另外还有两个小分支：“检查压缩逻辑”会生成一份让 Codex 检查候选稿逻辑的任务单（codex-compression-review-task.md）；“取消压缩”会删掉候选稿、指纹文件和检查任务单，原文不动。

流程 D：全文去 AI 腔

场景：你点了“全文去 AI 腔”。

1
收集精简材料 应用层 → 数据访问层

后端读出段落顺序和人物，人物的身份和性格简介各压缩到 240 字以内；读全文并严格检查标记，正文为空就停下。

用到的技术
  • Next.js Server Actions：调用 prepareStyleReviewTaskAction
  • Drizzle ORM：只读需要的几列：段落 ID、人物姓名和简介
对应文件
  • src/app/actions.ts所有按钮操作的后端入口prepareStyleReviewTaskAction
  • src/lib/style-review-task.ts准备去 AI 腔任务prepareStyleReviewTask
2
拼任务单并安全写入 数据访问层 → 存储层

把全文、段落顺序、人物简介和五类语言规则拼成任务单；写入前后都确认正文没被改，再替换成任务文件。

用到的技术
  • 模板字符串：拼出任务单
  • 临时文件 + 改名 + 内容比对：和扩写任务相同的安全写法
对应文件
  • src/lib/style-review-format.ts去 AI 腔的规则和任务单内容buildStyleReviewTask
  • src/lib/style-review-file.ts安全写入任务文件writeStyleReviewTaskFile
  • data/projects/<项目ID>/codex-style-review-task.md去 AI 腔任务单
3
Codex 直接修订正文 外部 AI

和压缩不同，这里没有候选稿：Codex 直接改 content.md 里各段标记之间的文字，不能改剧情和段落结构。回到网页时，按“扩写一段”第 7 步同样检查标记。

用到的技术
  • Codex（VS Code）：按任务单里的规则修订语言
对应文件
  • data/projects/<项目ID>/content.md正文

流程 E：导出正文为 txt

场景：你在浏览器里打开 /projects/<项目ID>/export 这个网址。

1
访问导出网址 应用层

目前页面上没有导出按钮，代码里有这个功能，直接访问网址就会触发。

用到的技术
  • Next.js Route Handler：route.ts 里的 GET 函数就是一个普通网址接口，有人访问就执行
对应文件
  • src/app/projects/[id]/export/route.ts导出接口GET
2
读正文并拼成纯文本 数据访问层

按段落顺序读出正文（严格检查标记），去掉标记，拼成一整篇文字；用项目标题做文件名。

用到的技术
  • Drizzle ORM：读段落顺序
  • Node.js 文件读写：读 content.md
对应文件
  • src/lib/story-export.ts拼接导出用的正文、处理文件名assembleStoryText、sanitizeTextFileName
3
让浏览器下载 应用层

返回文字时附带“这是附件”的说明，浏览器就会把它当成 txt 文件下载；出错时返回错误说明。

用到的技术
  • HTTP 响应头：Content-Disposition: attachment 让浏览器下载而不是直接显示
对应文件
  • src/app/projects/[id]/export/route.ts导出接口GET 的最后一段

流程 F：新建和删除项目

场景：你在首页新建一个项目，或点某个项目的“删除”。

1
新建项目 应用层 → 存储层

在一个事务里：数据库插入一条项目记录，同时创建这个项目的文件夹和空的 content.md；然后跳转到项目页面。

用到的技术
  • 数据库事务：数据库记录和文件夹一起创建
  • crypto.randomUUID：给项目生成一个不会重复的 ID
对应文件
  • src/app/page.tsx首页：项目列表和新建表单
  • src/app/actions.ts所有按钮操作的后端入口createProject
  • src/lib/project-content.ts所有读写 content.md 的代码都在这里createProjectContent
2
删除项目 界面层 → 应用层 → 存储层

先弹出确认框；确认后在一个事务里删掉数据库里的项目（人物、段落等会被一起删掉），并删除整个项目文件夹。没有回收站，删除是永久的。

用到的技术
  • 浏览器确认框：ConfirmButton 防止误删
  • 数据库外键级联删除：ON DELETE CASCADE：删项目时，属于它的人物、段落自动一起删
  • Node.js 文件删除：rmSync 删除项目文件夹
对应文件
  • src/app/ui.tsx通用小组件ConfirmButton
  • src/app/actions.ts所有按钮操作的后端入口deleteProject
  • src/lib/project-content.ts所有读写 content.md 的代码都在这里deleteProjectContent

7. 面试自测

先自己回答，再点开看要点。答不上来的，可以复制问题去问 AI。

数据为什么这样存为什么正文不放数据库，而放在 Markdown 文件里？

正文要能在 VS Code 里直接编辑，Codex 也要读写；数据库只管顺序和指令，两边用段落 ID 对应。

出错了会怎样如果你在 VS Code 改了正文，同时网页上点了保存，会怎样？

网页保存前会重新读文件，发现和打开时不一样就拒绝保存，提示刷新，不会覆盖你的新内容。

出错了会怎样写文件时断电，正文会不会坏？

不会。先写到临时文件，写完再一次性替换原文件，失败时临时文件会被删掉。

AI 怎么被约束怎么保证 Codex 只改了该改的段落？

每段正文被带 ID 的标记包住；写回前检查标记数量、ID、顺序和数据库完全一致，不一致就拒绝。

离上线差什么这个项目离“上线给别人用”还差什么？

现在是本地单人工具，下面这些是有意没做的。如果要给多人在线使用，需要补上：

#功能用途单人本地（现在）多人上线（需要）
1登录与账号知道现在是谁在用只有你一个人，不需要每个人要注册、登录
2权限与数据隔离每人只能看、只能改自己的项目所有项目放在同一个数据库，谁打开都能看按用户区分数据，别人看不到你的小说
3多人同时写入很多人同时保存时数据不打架SQLite 是单个文件，一个人用足够；用哈希防止你自己多个工具互相覆盖换成服务器数据库（如 PostgreSQL），处理同时写入
4部署上线别人能通过网址访问只在你电脑上运行（本机地址）部署到服务器或云平台，配 HTTPS 加密
5自动备份与恢复数据坏了能找回正文靠 Git，数据库没有备份定时自动备份数据库，能恢复到某个时间点
6操作审计查到谁在什么时候改了什么没有，只有正文的 Git 历史记录每次重要操作，出问题能追查和复盘
7日志与监控别人遇到错误时你能知道错误只打印在你的终端里错误保存成日志，严重时自动提醒你
8AI 调用让 AI 自动写，不用人工中转你手动把任务单交给 Codex接入 AI 接口，并控制费用、限制调用频率、失败自动重试
